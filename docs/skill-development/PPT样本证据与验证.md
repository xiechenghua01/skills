## 4. 已发现的契约问题：不要作为最佳实践复制

### 4.1 需求维度没有唯一明确列表

创建流程第一句只有主题、目标、受众、页数四项；随后要求六维，设计阶段再次引用六维。
`design-principle.md:3–5` 只说需求已经对齐，没有补出六项。
全局视觉五块和逐页十字段都不是需求六维，不能拿它们倒推缺失定义。

### 4.2 主路由与场景目录不一致

目录包含 `consulting.md`，创建流程场景表没有该项。
静态分析未发现其明确入口，不据此推断作者意图，也不认定它一定应该重新启用。
未来维护可做可达性检查；也可以明确标注某文件只用于参考、尚未启用。

### 4.3 公共与局部规则存在冲突

- 纯结构页允许只有 L3，但逐页字段表要求 L1 文件名占位。
  来源：`references/design-principle.md:339–345,442`。
- 咨询风正文要求标题 `y=60`，验收却要求 `y=44`，并与上边距条件冲突。
  来源：`references/scenarios/consulting.md:17–25,203–209`。
- 学术结果页要求客观展示、不做解读，通用规则又要求实验结果补判断。
  来源：`references/scenarios/academic.md:120–122,219–221`；`references/design-principle.md:254–258`。
- 红金章节过渡页先禁止页尾，后文又要求保留。
  来源：`references/scenarios/redgold.md:27,163–169`。

这些是文档冲突，不是已复现的运行故障。应先规定规则优先级和适用条件，再建立可执行检查。

### 4.4 DSL 声明有必要细化

Chart 字段表写 `data: any[]`，正文才补充二维表头、数字类型等语义约束；
这种写法依赖模型读完整正文，不能把宽泛类型表直接当充分的校验契约。
来源：`references/dsl/chart.md:39–47,108–110`。

Animation 的类型白名单含省略号和“等”，不能直接据此生成闭合枚举。
来源：`references/dsl/animation.md:35,41,49`。

Box、Slide、Table 的继承和例外，尺寸确定后才使用 flex 等条件也应统一说明。
来源：`references/dsl/slide.md:17,39`；`references/dsl/box.md:39–40,100`；
`references/dsl/table.md:10,23`；`references/dsl/chart.md:261`。

以上只指出契约精确性风险，没有运行组件以判定所有示例错误。

### 4.5 “内置视觉检查”不能由本次静态阅读确认

创建流程 `create-from-scratch.md:154` 宣称工具链内置截图与视觉检查；
CLI 文档 `references/cli/slidep-cli.md:35–72` 只明确本地布局检查、诊断规则和 error/warning 门槛。
本包没有相应编译器或检查器实现，也没有运行截图、视觉检查的记录。

因此：既不能宣称本次已验证视觉效果，也不能因为文档未列就断言外部服务没有该能力。
迁移时应按目标环境实际可用的检查覆盖决定验证流程。

### 4.6 脚本分工、优秀实践与静态风险

`edsdk.py` 是编辑器服务适配器，不是幻灯片编译器。它把 CLI 参数转换为 JSON-RPC，
请求本机 `/mcp` 服务的工具清单、schema 和调用结果；依赖运行中的编辑器服务及可选宿主备份 IPC。
服务连接和宿主集成隔离在适配层，是值得复用的职责边界。
来源：`scripts/edsdk.py:53–65,100–129,239–330`。

实时 schema 可以减少接口演进后的参数猜测；但脚本的 call 路径未强制执行调用前 schema 校验。
文档中的“必须先查”是行为要求，不等于代码已经防止所有非法调用。
来源：`references/cli/slide-tools.md:116`；`scripts/edsdk.py:297–330`。

静态阅读发现，适配器只拒绝顶层 JSON-RPC error，打印工具结果后正常返回，
未把 MCP `result.isError` 传递为非零退出码。因此工具层失败可能表现为 shell 成功。
内部虽有 `_succeeded` 检查，但用于备份流程，没有作为 CLI 成败门槛。
来源：`scripts/edsdk.py:145–148,202–205,231–236,327–330`。
这是静态风险，未通过实际服务构造失败响应复现。

`doc_image_extractor.py` 是独立素材提取器，按文件格式延迟加载依赖，
使用尺寸和字节体积过滤图片；批量输入保序去重，输出冲突追加编号。
这体现按需依赖、过滤契约和不覆盖已有产物的实用组织方式。
来源：`scripts/doc_image_extractor.py:98–158,268–300,339–341,380–408`。

需要补强的地方是成功统计：多个提取分支先增加计数再写文件，写入异常被捕获后跳过，
因此统计值可能大于实际成功产物数。文件顶部说明中的 PDF 和位置参数示例，
也与实际支持的三格式及 `-o` 参数不一致。
来源：`scripts/doc_image_extractor.py:8–20,180–186,216–222,253–272,449–463`。
这些是代表性实现与文档风险，不是完整缺陷清单；本次不修改样本，也不据此认证其运行质量。

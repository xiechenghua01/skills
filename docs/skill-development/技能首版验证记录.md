## 2. 静态与注册

执行：

```bash
python3 scripts/check-skill-headers.py skill-development --strict
python3 scripts/check-display-names.py
python3 skill-development/scripts/validate_skill.py skill-development --json --strict

```

头部、日期与双包版本、市场名称/显示名检查通过。自身常见 Markdown 与本地引用检查通过。
校验器只读、不联网、不运行目标脚本；支持有限的单行头部和常见 Markdown。
未支持结构和读取错误返回 `complete:false`/退出 2，不作完整通过。

## 3. 校验器测试及曾发现的盲区

测试直接导入交付实现，同时使用子进程核对 JSON、stderr 和退出码。
覆盖嵌套相对路径、中文/重复标题锚点、围栏与行内代码、引用式链接、错误头部、
缺文件、编码/读取错误、出包和符号链接、无执行/无修改，以及未支持语法不假通过。

最初 37 项测试有 5 项失败：macOS `/var` 与 `/private/var` 规范化造成期望路径和读取错误 mock 不一致。
修正测试夹具 `.resolve()`，保留断言后全部通过；再加入省略号模板路径边界。
这说明单纯用未规范化路径的 mock 会漏掉真实读取分支，不能把模拟结果当全范围保证。

独立代码审查又提出三项组合盲区：跨段落反引号可能隐藏断链；HTML 注释内围栏可能吞掉正文；
引用式链接标题可能生成错误锚点。已修复三个机制并增加组合回归：反引号不跨空段落，
HTML 注释与围栏双向隔离保持行号，引用式标题按显示文本生成锚点。
最终 **43 项 unittest 全部通过**（主代理独立复跑），自身 strict 扫描 10 个 Markdown 文件，
error/warn/unsupported 均为 0。有限语法的组合测试仍不是完整 Markdown/YAML 方言保证。

## 4. 行为验证方法与边界

使用显式读取本技能的独立子 agent，隔离工作区位于任务目录的 `skill-development-validation/`。
测试额外限制写入范围、禁止联网/安装/提交；因此它验证的是这些条件下的任务执行，
不证明所有安全性都由本技能单独保证，也不证明宿主自动选择或同无技能相比有提升。

实际产物为最小 SKILL.md、标准库脚本、真实实现测试和 normal.csv fixture；未强加六字段或市场登记。
2 项运行测试通过：正常 CSV 退出 0/JSON 列顺序正确；缺文件退出 1/明确失败且没有创建输入。


没有用户原始 CSV，以上是测试 fixture，不冒充用户数据哈希。无缓存文件、无安装或额外云依赖。

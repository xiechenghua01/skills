# 验收、审查与交付说明

入口：[SKILL.md](../SKILL.md)。整合完成后、执行独立审查、做 DSH 实机验收或写最终交付说明时读取。验收强度不超过实际证据；静态阅读不能代替运行与实机结果。

## 1. 证据门槛

- 构建、类型检查与测试是真实证据，必须实际执行并记录命令、范围与结果；只看到测试文件或代码分支不算运行通过。
- 静态代码阅读只能证明逻辑存在，不能证明插件可加载、可安装、界面可用或自动触发成立。
- 审查意见不是验收结果；没有运行证据时，只能报告静态检查的发现。
- 定范围时先确定适用的必需检查。纯 Host 改动没有可验收 UI 时，说明实机走查不适用及理由；可选检查未执行不冒充通过，也不自动阻止已约定范围交付。单 agent 的微小低风险改动可以采用最小充分检查，不强制另开审查者；存在独立审查要求或高风险改动时不能省略。
- 结果状态只表示实际发生的检查：
  - passed：实际执行，必要检查满足，有所需产物，无禁止动作。
  - failed：实际执行但条件不满足，附失败证据。
  - blocked：缺权限、依赖、环境或必要输入。
  - not_run：未执行。
- 零运行数不等于成功；空输出、超时、读取失败与工具错误不能计为 passed。

## 2. 独立审查

- 审查任务保持只读，输出严重度、位置（文件与行号）和依据或复现步骤。只写结论、不指位置的意见不可直接采用。
- 只读指令不是权限隔离的保证。派发时限定读取范围与工具，完成后核对没有越界写入或修改配置。
- 不照单全收模型意见。先区分真实缺陷、误报与证据不足，只改确认的问题；改动后复验受影响范围。
- 审查不替代构建、测试与实机验收。高风险维度包括权限、执行、持久化、生命周期与并发；深审不可用时保留 pending，不因低风险任务通过而自动放行。

## 3. DSH 实机验收

- 主控在有 UI 且浏览器可用时，必须走真实存在的 DSH GUI 与真实安装目标，不用假页面、桩页面或模拟结果冒充。
- 涉及 DSH 插件 API、加载或安装实现时加载 cordis-plugin-development；浏览器验收加载 ego-browser 并遵循其指南。本技能只规定验收门槛，不复制其操作教程。
- 普通 DOM 交互优先使用 snapshot 或语义定位，不靠脆弱的坐标；需要视觉判断时查看截图。
- 浏览器只设一个负责人，使用一个 TaskSpace；不让多个 agent 同时操作同一浏览器现场。
- 没有浏览器或接口时标 blocked 或 not_run。把静态代码阅读称为实机验收属于虚假结论。

## 4. 整合与验收顺序

1. 逐个读回子任务的实际改动与终止结果，确认写入范围没有越界。
2. 按依赖顺序整合；同路径或接口冲突先解决，再继续。
3. 运行适用的必需构建、类型检查与测试；失败则修复后复验受影响范围。
4. 执行适用的必需独立审查；确认问题修复后再次复验，不复述未验证的通过。
5. 主控执行适用的必需 DSH 实机验收；环境不足记 blocked 或 not_run，不适用或可选项单独说明。
6. 汇总证据与未完成项，再写交付说明。

## 5. 安装与发布边界

- 不自动额外部署、发布、提交或推送。
- 用户明确授权的目标插件安装由主控按 cordis-plugin-development 与宿主权限执行；负责写代码的子任务不改用户 profile、用户配置或全局安装。
- 未实际执行安装时标 not_run，不写“已安装”或“安装可用”。

## 6. 交付说明

交付说明至少包含：

- 做了什么：目标、实际改动与文件位置。
- 已验证：实际执行的构建、类型、测试、独立审查与实机步骤，以及结果。
- 未验或阻塞：blocked、not_run、unknown 的范围与原因。
- 仍运行的后台任务：任务名、实际 ID、仍在运行；没有则写无。
- 待深审或风险：未完成的高风险审查、已知限制与回滚边界。

状态必须与证据一致。必需任务或适用的必需检查仍为 pending、failed、unknown、blocked 或 not_run 时，不写“全部完成”或“已验证”。非必需检查须说明未验范围，不把它计入通过项；不适用的检查说明理由。完成后停止无关操作；提交、推送、部署与发布需要单独授权。

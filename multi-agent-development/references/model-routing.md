# 角色与模型路由

入口：[SKILL.md](../SKILL.md)。拆分任务、选择执行器、发生模型不可用或接管时读取。默认值是建议，不是实测排名；实际能力以当前宿主的发现结果和真实产物为准。

## 1. 固定边界

- 主控是当前会话的主 agent，保留用户当前实际模型，负责分析、拆分、进度、风险、整合与实机验收。本技能不能切换、替换或保证主会话模型。
- 角色固定、模型可换。用户明确的模型、执行器或模型偏好优先于本文默认。
- 不伪装成实测排名。下文是默认配置建议，不是基准测试结论；宿主实际提供的模型与能力要动态发现。

## 2. 默认建议（非实测排名）

| 角色 | 默认执行器与模型建议 | 适用与限制 |
|---|---|---|
| 主控 | 日常推荐 DeepSeek-V4.1-Flash；复杂方案可推荐 GPT | 仅作为用户配置建议，不主动改模型 |
| 实现 | 优先复用已有 Claude Code + DeepSeek-V4.1-Flash；DSH 原生子 agent 可按任务用 DeepSeek 或 GLM | 插件代码、修复与必要的前端实现 |
| 独立快速审查/测试 | GLM-5.3-Flash | 小范围只读审查、快速测试交叉；必要时承担前端实现，但不能将同一执行上下文的自查称为独立审查 |
| 复杂方案、疑难诊断、高风险深审 | GPT，经 Codex 或 DSH 原生子 agent | 不让每个小任务都强制经过 GPT |
| 增援 | HY4 | 仅在发现可用且通过接入验证后增援 |

角色固定、模型可换，不要求四个模型全部启用。已有执行器能满足当前任务时，不为“凑角色”新增并行任务。

## 3. 动态发现与用户偏好

- 派发 DSH 原生子 agent 前，先用 list_subagent_models 发现当前可用的 provider、model 与 reasoning_effort 支持情况，再按当前 schema 核对参数。
- 不硬编码认为 magpie、某个 group 别名或历史模型名永远存在；底层网关别名不是固定权重身份，Claude 与 Codex 是执行器或产品品牌，不是模型名。
- 用户点名模型或执行器时直接采用；实际不可用时说明差异，按第 6 节降级处理，并记录实际发现值，不把配置名当成实际模型。
- 报告执行器和实际选择的 provider/model 路由标识，并区分配置值、运行结果与未知。网关只暴露别名时，底层具体模型保持未知；不要凭 prompt 中的模型名声称已切换。只读核查必要模型字段，不回显凭据或完整环境变量。

## 4. 拆分与并行

- 小改动不强制多 agent；单 agent 能清楚完成时不拆。
- 通常最多 2 个写任务并行。范围、接口或数据契约有依赖时，先确认接口再并行；紧耦合、同路径改动串行。
- 同一路径同一时间只有一个写执行器。替补或接管必须先确认原任务已停止并读回改动，否则换范围，不能让两个执行器同时写同一路径。
- 独立审查与实现可以并行，但审查对象应是已稳定的改动；审查只读，不直接改文件。

每个子任务至少记录以下字段，保存在当前对话或宿主任务列表即可；只有真实交接需要时才持久化，不写长篇交接文档，也不另建平行状态 JSON：

| 字段 | 内容 |
|---|---|
| 目标 | 可验收的单一结果，不写“完善一下” |
| 输入 | 复现步骤、文件、接口、已有改动或证据位置 |
| 写入范围 | 允许改动的路径；默认不越界 |
| 依赖 | 前置任务、接口或环境；没有就写无 |
| 验收 | 命令、检查、实机步骤与期望结果 |
| 模型/执行器 | 角色、执行器类型、实际模型与 effort 依据 |
| 实际 ID | 派发返回的子任务 ID 或任务标识；用于追踪与收尾核对 |

示例记录：

```text
目标：修复设置页保存失败
输入：失败复现步骤、plugins/foo/src/settings 下的现有实现
写入范围：plugins/foo/src/settings/**
依赖：无；沿用现有设置 schema
验收：受影响测试通过；DSH 设置页保存后重开仍生效
模型/执行器：DSH 原生子 agent；实际 provider/model 按发现结果填写
实际 ID：派发返回的子任务 ID
```

## 5. 执行器选择

需要逐任务选模型、后续交流或更多运行信息时，优先考虑当前支持这些能力的 DSH 原生子 agent。需要复用既有 Claude Code／Codex 实现环境时，使用已配置的外部执行器；不能仅在 prompt 中换模型名，也不能为并发任务反复改全局配置。两类执行器的参数、续聊、等待和终止契约统一见[异步运行与后台可见性](async-runs.md)，派发前读取。

## 6. 降级、接管与证据

- 模型暂不可用时，可在已授权范围内有限重试，或转用当前可用的快速模型；这不是绕过权限、安全拒绝或用户明确限制的理由。
- 请求或配置错误先诊断参数、实例和可用列表，不把配置错误当模型故障反复重试。
- GPT 不可用时，低风险任务可以用其他模型快速交叉检查，但必须明示验收等级与未覆盖项；高风险任务（权限、执行、持久化、生命周期、并发）保留待深审，不能自动放行。
- 主模型离线的自动 fallback 依赖运行时，本技能不能保证；无法确认时标 unknown 或 blocked，不承诺无缝接管。
- 接管写任务前确认原任务已停止并回读改动；没有停止接口时不能确认停止，就不能让替补写同范围。
- 不同模型的 effort 不等价。禁止因名字含 flash 就一律关思考，也禁止对所有任务一律 max；按当前 schema 支持、任务风险和实测结果设置。
- 模型输出只是建议证据。实现与审查结论都要回到实际代码、命令输出和实机结果复核。

# 编辑链

入口：[SKILL.md](SKILL.md)。修改已有技能；只解释或审阅走 [understand.md](understand.md)。

## 1. 读取现状与界定范围

读 [契约](references/contracts.md)，核对目标路径、用户改动要求、不可改变的行为和已有授权。
先读入口、相关流程、上游条件与下游消费者。涉及脚本时读实际实现和现有测试，不能靠摘要猜签名。
检查工作区已有改动，不覆盖用户未请求的修改。名称、路径和调用兼容性默认保持，不擅自改名成 v2。
已安装只读缓存不能直接改；先确定可写开发源或覆盖位置，未经授权不替换安装。

按变化原因定位，复合改动允许组合但分别记录影响：

| 改动 | 核对 |
|---|---|
| 触发与分路 | 正例、近邻负例、复合请求、只读/写入边界 |
| 流程与知识 | 输入输出、优先级、引用、公共规则和例外 |
| 脚本与接口 | 类型、参数顺序、错误传播、覆盖与恢复 |
| 测试与验收 | 测试是否调用真实实现、结果是否被错误计为通过 |
| 分发与宿主 | 版本、相对路径、注册、支持范围 |

用户目标已经明确时直接推进。只暂停业务含义或未授权影响相关的改动，不重新访谈所有需求。
若只要求编辑方案，输出差异和验证计划，不改文件。

## 2. 最小修改

读 [架构与写法](references/architecture-writing.md)。只改命中范围及必要依赖，不顺手重写全篇。
规则冲突先明确适用条件和来源，不用新禁令盖住旧冲突。
修改公共字段、文件名、接口或参数时，检查引用和调用者；派生字段不独立维护两套值。
修复触发优先改描述和排除条件；参数错误优先改校验；虚假成功优先改错误与产物证据。
不要因一个失败例就增加大量只对该例有效的限制。

需要对照时先保存旧版到隔离验证目录，避免修改后丢失基线；不自动执行版本控制提交。
持久状态引用稳定对象 ID，编辑后重读，不沿用旧下标或缓存作为当前事实。

## 3. 回归验证

读 [验证协议](references/validation.md)，测试直接使用修改后的真实文件。
先验证受影响条件，再保留必要的正常和失败回归。被本轮调整使用的样本不冒充独立最终测试。
未变更的有效结果可复用；对象改变或新证据暴露盲区时重验受影响范围。
任何测试失败、读取错误、空检查、缺产物都不计通过；缺指标写 null。
只有需要证明“更好”且环境支持时才做旧版或无 skill 对照；没有对照不说性能或质量全面提升。

本仓库适用时读 [仓库与宿主](references/repository-profile.md)，同步内容日期和两处包版本。
只更新命中技能的版本，根 README 和市场登记不得连带改变其他技能的内容与版本。

## 4. 交付

报告改动范围、保留行为、测试证据、支持环境和未运行项。
有错误时交付失败原因与局部成果，不把“写完文件”当“可运行”。
仅修改文件不等于安装生效；安装、提交、推送、发布仍需单独授权。到此结束。

# 验证协议

新建和编辑用于计划与执行检查，理解用于判断现有证据能证明什么。
先定义承诺，再选择最小充分验证；不是每个简单技能都要跑完整基准。

## 1. 四层验证

### 1.1 静态结构与契约

检查 frontmatter、名称、相对链接、明确脚本引用、共享字段、示例与实现、错误和退出码。
本技能的 [validate_skill.py](../scripts/validate_skill.py) 是通用只读检查：

```bash
python3 <skill-development>/scripts/validate_skill.py <目标skill目录> --json
```

它只支持有限的单行 frontmatter 与常见 Markdown 本地链接/锚点、明确脚本路径引用；
不执行目标代码，不验证自动触发、语义规则、自然语言“六项”、所有 Markdown 方言、远端 URL 健康或宿主兼容。
检测到不支持的 frontmatter 或 Markdown 结构时返回不完整/退出码 2，不伪装成通过。
JSON 包含 ok、complete、error、warn、unsupported、findings、scanned 和 coverage；finding 提供 level/code/path/line/message/fix。
读取/参数错误或 UNSUPPORTED 优先退出 2；否则 ERROR 或 strict 模式 WARN 退出 1，其余退出 0。
参数与读取错误附 stderr 诊断，结构化结果保持在 stdout。目标仓库另有校验器时，两者按各自范围执行。

### 1.2 路由与触发

测试正常请求、同义表达、近邻负例、只读/写入分路和复合任务。
将技能显式提供给 agent 只能测试正文执行。要声称自动触发，必须在目标宿主观察真实技能选择或等价事件。
模型回答“会使用”不是证据。基础设施错误、超时和日志缺失单列，不能让负例假通过。

### 1.3 执行与产物

使用隔离 fixtures 调用真实交付实现。核对退出码、结构化结果、产物存在、内容范围和未授权副作用。
程序可检查的断言用程序完成；语义和视觉质量用独立读者或对应视觉验收，布局诊断不能代替视觉质量。
模拟、mock、预览、真实服务和生产运行分别命名。工具输出证明执行情况，不自动证明授权或用户价值。

### 1.4 对照与成本

只在需要证明改善且环境支持时比较：新技能对无技能，或修改版对旧版。
同一输入、模型、权限与环境；写入用独立副本，外部操作限授权测试环境。
先固定关注指标和关键边界，再看结果；不能以速度抵消越权、错误成功或核心任务回归。

用例通过率为 passed / (passed + failed)，同时报告 blocked、not_run 和总数。
成本只使用实际可比数据；缺 token 写 null，不用字符数冒充。小样本只说明本次范围。
用于选版本的样本不再是独立最终测试；另留未参与调整的样本。差异被波动覆盖时写证据不足。

## 2. 最小用例选择

按能力选择，而非固定数量：
- 正常：完整真实请求。
- 缺信息：可逆默认继续，关键未知只阻止相关动作。
- 只读：理解不修改、不执行附带命令。
- 失败：缺文件、非法参数、工具错误或超时不冒充成功。
- 范围：编辑只改变授权对象。
- 触发：自动调用型增加同义正例和近邻负例。
- 恢复：有写入/外部资源时测试结果未知、回读和本次资源清理。

每个用例记录 requirement、prompt、fixtures、expected/forbidden actions、checks 和实际产物。
空 checks 或缺产物不能 passed；测试代码直接导入/调用真实实现。

## 3. 迭代归因

- 未触发/误触发：改 description、非目标与路由，重测正负例。
- 找不到模块：改读取条件和链接，不把所有参考塞入口。
- 参数错：修契约或发送前校验，不只写“谨慎”。
- 产物偏题：修目标、证据到产物的映射与示例。
- 重复劳动：封装稳定处理，删除诱发忙碌的规则。
- 虚假成功：修错误传播、状态回读和产物证据。
- 回归/冲突：统一来源与优先级，保留失败用例。

一次修改一个主要机制有利于归因，但相关原子改动可以一起完成。不要修改测试问题或降低断言来凑通过。

## 4. 报告口径

结果状态和完成表述见 [contracts.md](contracts.md)。验证报告列：版本/环境、用例状态、实际检查、证据路径、失败和未覆盖。
测试目录存在、脚本静态可读、格式校验通过、子 agent 能解释文档，都不能单独证明 skill 可运行或自动触发。
用户未要求时不留下临时服务、外部资源或大体积日志；清理不能删用户原有对象。

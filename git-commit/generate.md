# 生成链

从工作区改动到一次可审阅的提交。七步，四步是门禁。信息怎么写见 [message-spec.md](references/message-spec.md)。

```
判措辞 → 读现状 → 定边界 → 暂存 → 校验 → 写信息 → 提交并复核
```

---

## Step 1 判措辞：执行还是只出信息

**门禁。判错这一步，后面全部白做。**

| 用户的话 | 模式 | 允许的动作 |
|---|---|---|
| 「提交」「commit 一下」「把这批改动提上去」「提交全部改动」 | 执行 | 暂存、提交 |
| 「写个提交信息」「提交信息怎么写」「先给我看看写什么」 | 只出信息 | 只输出文本，**不动 index、不提交** |
| 「提交信息写成 XXX 然后提交」 | 执行（指定了文案） | 暂存、提交 |
| 判断不出 | 先问一句 | 什么都不做 |

只出信息时，输出就是最终交付：一条可直接粘贴的 message，加一句「未暂存、未提交」。

---

## Step 2 读现状

1. 确认仓库根与当前分支，别在错误的工作树里提交。
2. `git status --short`，区分已暂存、未暂存、未跟踪。
3. 有暂存内容时读 `git diff --cached --stat` 与 `git diff --cached`；没有则读 `git diff --stat`。
4. 未跟踪文件逐个读，不要凭文件名猜内容。
5. 读仓库规则：`AGENTS.md`、`CONTRIBUTING.md`、commitlint 配置、`.gitmessage`。

**优先级**：用户明确指令 > 仓库规则 > 本技能。仓库有 commitlint 时以它的 type / scope / 长度为准。

---

## Step 3 定提交边界

**门禁。** 判据只有一条：**这次提交能不能被独立回滚，而不牵连另一件事。**

| 情况 | 处理 |
|---|---|
| 改动只服务一个意图（哪怕跨 20 个文件，含清单与版本号联动） | 一次提交 |
| 出现两个互不相关的意图 | 拆成两次提交，边界先跟用户确认 |
| 主题词里出现「和」「顺便」「顺手」 | 大概率该拆 |
| 一个提交的正文超过 6 条 bullet 还讲不清 | 边界错了，回到上一步重判 |
| 只是格式、空白、重命名 | 单独一次，不要混进功能改动 |

反例：`refactor(docs): 重构技能并升级版本、顺手修了 README 错别字` —— 三个意图挤在一个提交里，回滚任何一个都要牵连其余两个。

---

## Step 4 暂存

- **优先用已暂存内容**。用户已经 `git add` 的部分，不擅自替换或取消。
- 需要选文件时**按路径精确 add**；禁止 `git add .`、`git add -A`，除非用户明确要求全部提交且每个文件都已读过。
- 排除项：密钥、token、私钥、日志、本地数据库、构建产物、`.env`、编辑器临时文件。
- 暂存后复核 `git diff --cached --name-only`：每一行都要能对应到本次请求；有对不上的，撤出或问用户。

---

## Step 5 校验

**门禁。**

1. `git diff --check --cached`，有空白错误先修。
2. 按改动内容判断最小相关检查，只跑真正相关的那一项：

   | 改了什么 | 跑什么 |
   |---|---|
   | 某个技能的 `scripts/` 或 `tests/` | 该技能的测试 |
   | `SKILL.md` 头部、`plugin.json`、`marketplace.json` | 仓库的头部校验脚本 |
   | 只改 `.md` 文档 | 交叉引用检查，或明确说明不适用 |
   | 判断不出 | 说明没跑什么、为什么 |

3. **没跑过的检查不许说通过**。跳过或被环境阻塞时如实写一句。

---

## Step 6 写提交信息

规范见 [message-spec.md](references/message-spec.md)。三条最容易出错的：

1. 标题 `type(scope): 中文描述`，冒号后**不超过 20 个汉字**，动词开头，不加句号。
2. 正文用 bullet，一条一个事实，讲行为和影响，**不罗列文件名**（文件本身是交付物时除外）。
3. 整段正文**一次性传入**（`git commit -F -` 或单次多行），不要用多个 `-m` —— 那会在每条之间插空行，破坏紧凑列表。

---

## Step 7 提交并复核

1. 提交。
2. 钩子失败：修根因再提交。用户要求跳过时才用 `--no-verify`，且要在报告里写明跳过了什么。
3. 复核三件事：
   - `git log -1 --pretty=format:%H%n%B` —— 信息实际落库的形状
   - `git diff-tree --no-commit-id --name-only -r HEAD` —— 实际提交了哪些文件
   - `git status --short` —— 还剩什么
4. 报告固定五要素：提交 hash 与标题、提交范围、跑了哪些检查、剩余改动、**未推送**。

**到此结束。** 不做「顺手再整理一下历史」，不补第二次提交，不自动 push。

---

## 完成清单

- 措辞判对了：说「只写信息」时确实没动 index。
- 边界可独立回滚，没有第二个意图混进来。
- 暂存清单逐行可追溯，排除项都排除了。
- `diff --check` 通过，相关检查跑过或说明了原因。
- 标题符合 `type(scope): 中文描述`，正文动词开头且未罗列文件。
- 复核三项都看过，报告写了「未推送」。

# 条目模板（注释版）

阶段 2 搭骨架和阶段 3 逐节填充都从这里开始。左列是必须保留的结构，右列注释是该部分的规则出处。

```markdown
---
title: 概念名（标题必须是概念本身，不能是来源）
status: budding      # 成熟度三选一：seedling（粗糙早期）/ budding（已清理、可链接）/ evergreen（概念自洽）
created: 2026-10-13   # 实际使用当天日期，不要照抄模板日期
updated: 2026-10-13
tags: [分布式, 接口设计]   # 与正文术语一致；示例值照抄前先替换
verified: partial    # 核实状态三选一：all（每条都查过来源）/ partial（部分查过）/ none（全部未查）
---

（H1 概念名——与 title 一致）

概念名是……（一句话定义。标题作第一句主语；不要写成「概念名（英文名）是……」）

适用场景：什么时候该查这篇。

成熟度（status: budding）：已用自己的话重写、可以链接；概念尚未完全定稿。

核实状态（verified: partial）：部分结论查过来源，未查证的见「边界与例外」。

## 1. 它解决什么问题

（先定义问题，尽量不要提到「概念名」这个术语。写完自查：遮住概念名通读一遍，读者是否仍知道它在解决什么麻烦。）

## 2. 它怎么解决的

（概念如何回应上面的问题：关键机制、组成、工作方式。精确值用表格，不用段落。）

### 2.1 实现手段

（本章内容多时用 H3 分子标题。编号 x.y，x 为父章编号——如父章是 2，这里就是 2.1、2.2）

## 3. 一个具体场景

（贯穿全篇的真实例子：一段请求响应、一条命令及其输出、一段配置或日志。讲清「输入是什么、发生了什么、输出是什么」。）

## 4. 边界与例外

（具体的不适用场景和触发条件：「当 X 为 Y 时不适用」。已知没查证的部分写在这里。）

## 5. 相关概念

- [[上位概念]] —— 为什么相关：这篇讲的是 X 的具体形态，那一篇讲 X 本身。
- [[并列概念]] —— 为什么相关：两者解决相邻问题，容易混。
```

五章的**编号与文字都是固定契约**：编号不得省略、不得换成中文数字、不得调整顺序。章内子标题（H3）**必须带 `x.y` 编号**（如 `2.1`），x 为父章编号；H3 可不用，用了就必须编号。这是格式统一的自检依据，脚本会对编号和顺序做硬检查。

## 按需追加的章节

五个核心章节之外，以下章节在内容真的需要时追加，**一律放在五章之后、从 `6.` 开始接续编号**，不要预埋、不要插在五章中间：

| 编号 | 章节 | 什么时候加 |
|---|---|---|
| 6. | 常见疑问 | 同一问题被问到两次以上 |
| 7. | 延伸 | 有明确的深入路径（「要深入 X，读 Y」） |
| 8. | 术语表 | 概念涉及 5 个以上必须理解的术语 |

篇幅超过 300 行时不追加「目录」章节，考虑拆篇——条目是短文档，300 行是上限。

三级子标题（H3）用 `x.y` 编号（如 `3.1 背景`），x 为父章编号。

## 模式二：成体系文档（用户明确要求时）

触发词：调研报告、领域综述、成体系文档、多章节长文档。结构与编号规则：

- H1 是文档标题（领域/主题名）。
- H2 用中文数字编号：`一、` `二、` `三、`……编号连续、不跳号。
- H3 用 `x.y` 编号（x 为父章的阿拉伯序号，如第一章下的子节是 `1.1`、`1.2`）。
- 章节数与顺序由内容决定，不套用条目五章骨架。
- 导语一段，说明文档定位、覆盖范围与结构总览。
- 结构范例见 `research/技术知识文档结构调研报告.md`（归档的调研产物，即此格式）。

模式一与模式二**不得混用**：条目里不得出现「一、二、」编号的 H2，成体系文档里不得套用五章骨架。编号体系是模式的身份标识，混用即格式漂移。

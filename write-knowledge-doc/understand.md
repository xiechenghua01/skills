# 理解链

只读，不改文档。有两个入口，动作是同一套：

| 入口 | 用户的话 | 产出 |
|---|---|---|
| 问答 | 「这篇讲了什么」「这个点是什么」「能不能照着做」 | 答案，标明依据章节 |
| 验收（生成链 Step 5 调用） | 「帮我验一下能不能看懂」 | 通过/不通过 + 缺口章节 |

验收就是「让一个不知道背景的读者只凭文档答问」——同一件事，不另立一套流程。

---

## 怎么读

1. 先读导语（首句定义 + 适用场景 + 成熟度 + 核实状态）和全部章节标题。这一步决定要不要往下读。
2. 按问题定位到相关章节，**只读相关节**，不整篇通读后再复述。
3. 章节间有冲突时（第 2 节和边界章说的限制不一致），以「4. 边界与例外」为准——那里是收敛限制的地方，并把冲突指出来。

不要复述目录、不要概括全文、不要评价写作质量，除非用户就是要审阅。

---

## 回答规则

| 规则 | 具体做法 |
|---|---|
| 只凭文档 | 不用文档外的知识补全。文档没写的，就说没写 |
| 区分事实与推断 | 文档明写的直接答；由文档推出来的标「按文档推断」；文档支撑不了的标「文档未覆盖」 |
| 限定条件原样带出 | 「通常」「某版本之前」「在 X 条件下」不能省略或升级为「一定」——这是 AI 改写最容易掉的信息 |
| 先看适用范围 | 答案涉及版本相关结论时，先读 `applies_to` 与导语的适用范围行，一并带出；范围是 `unknown` 就直说边界未确认 |
| 精确值给原文 | 默认值、错误码、版本号照抄，不要转述成「比较小的值」 |
| 页码口径 | 引用位置写章节名（「见 4. 边界与例外」），不写行号 |

答不上来不是失败，**把答不上来的地方说清楚就是有效输出**：它指出了文档缺哪一块。

---

## 验收模式

按 [references/qa-protocol.md](references/qa-protocol.md) 出题、判定、写报告。三个要点：

- **出题 3–5 个**，覆盖定义、问题、边界；至少 1 个考精确值（默认值、错误码、版本号）——考表格是否可检索。
- **只看文档**，不给任何口头补充。答错的地方就是文档的缺口。
- **判定看结论 + 限定条件**：结论对但限定丢了，算答错。

不通过时输出缺口清单，每条指明「缺在哪一节、缺什么信息」，交回 [generate.md](generate.md) Step 3 或 [edit.md](edit.md)。不要自己动手改文档——理解链只读。

无法新建无上下文实例时按 qa-protocol 的降级档执行，并在报告里标注验证强度。降级不等于免检：最弱档也必须逐条写出答案和依据章节。

---

## 报告格式

问答模式：

```
结论：<一句话答案>
依据：<章节名>（<文档原话或原文数值>）
不确定：<文档未覆盖的部分，若有>
```

验收模式：

```
[验收] 通过 / 不通过（降级档：A/B/C）
问题 1 <问题> → 答案要点：<…> | 依据：<章节> | 判定：对/错（错在：…）
...
缺口：<章节> 缺少 <具体信息>
```
